Это решено — не пересматривать в процессе реализации.

| Решение | Значение |
|---|---|

| Название сайта | **Swedish** (`<title>Swedish</title>`, `name` в PWA, логотип в шапке) |

## 1. Концепция

**Статическое веб-приложение для изучения шведского**, размещённое на GitHub Pages, **без бэкенда**.

Основной цикл:

1. Ученик выбирает **тему** (урок) из трека уровня.
2. Урок показывает **короткую теорию** и/или **список слов**, с озвучкой.
3. Ученик нажимает **«Пройти тест»** → 10 вопросов из пула ~100.
4. За прохождение начисляются **XP** (мера обучения) и **монеты** (валюта для трат).
5. Монеты тратятся на **строительство Стокгольма**: от первобытного племени через эпоху
   викингов до современного города.
6. Здания дают **бонусы**, которые возвращаются в обучение (множители XP, больше повторений,
   тематические паки уроков) — цикл замыкается.

Главный принцип: **много разных способов учить шведский, каждый с позитивным подкреплением**.
Никаких наказаний. Нет жизней, нет провалов, прогресс не сгорает. Ошибка означает лишь то,
что вопрос вернётся в повторение раньше.

## 2. Цели и не-цели

### Цели

- Быстрая локальная разработка: `npm install && npm run dev` — и приложение работает за 10 секунд.
- Контент — это **данные, а не код**: добавление урока не требует правки исходников.
- Полностью статическая сборка, деплой на GitHub Pages одним GitHub Actions workflow.
- Весь прогресс хранится локально (localStorage) с **экспортом/импортом** файла сохранения.
- Две параллельные таксономии: **CEFR** (A1, A2, B1, B2, C1) и **SFI** (Kurs A, B, C, D и
  Grund 1–4 / Grundläggande svenska). Один урок может входить в обе.
- Несколько режимов изучения темы, не только тесты.
- Типизированный и валидируемый контент: сломанный файл урока валит CI, а не браузер ученика.

### Не-цели (для v1)

- Нет сервера, аккаунтов, базы данных, мультиплеера.
- Нет платного TTS и хостинга аудиофайлов — используем Web Speech API браузера.
- Нет нативных мобильных приложений (достаточно PWA).
- Нет генерации контента ИИ в рантайме.

## 3. Стек

| Задача | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript** (strict) | Схемы контента и состояние геймификации сильно выигрывают от типов |
| Сборка | **Vite** | Мгновенный HMR, простой статический вывод, отличная поддержка GitHub Pages |
| UI | **React 18** | Самая большая экосистема, низкий порог входа |
| Роутинг | **React Router**, `HashRouter` | Хеш-роутинг работает на GitHub Pages без настройки сервера |
| Состояние | **Zustand** + `persist` | Минимум кода, персист в localStorage из коробки |
| Стили | **Tailwind CSS** | Быстрая итерация, консистентные отступы и цвета, тёмная тема сразу |
| Загрузка контента | `import.meta.glob` (eager) | Автообнаружение файлов уроков, нет ручного индекса |
| Валидация | **Zod** | Одни и те же схемы в CI и в дев-режиме рантайма |
| Markdown | `react-markdown` + `remark-gfm` | Теория пишется в Markdown |
| Тесты | **Vitest** + **@testing-library/react** | Общий конфиг с Vite, ноль настройки |
| Озвучка | **Web Speech API** (`speechSynthesis`, `sv-SE`) | Бесплатно, офлайн, без ассетов |
| Иконки | **lucide-react** | Единый стиль, tree-shaking |

> **Рассмотренная альтернатива:** SvelteKit или Astro со статическим адаптером. Оба отличные,
> но React + Vite даёт наименьшее трение и самую большую экосистему компонентов.
> Если проект станет резко контент-ориентированным, Astro будет лучше — вернуться к этому в v2.

### Почему уроки лежат в папке CEFR, но принадлежат многим трекам

Урок — это **единица контента**. Учебный курс — это **упорядоченный плейлист из id уроков**.
`content/curricula/sfi-b.json` и `content/curricula/cefr-a1.json` могут оба включать
`a1/greetings` — без дублирования и симлинков. Путь в файловой системе нужен только человеку
при редактировании; приложение не выводит из него ничего, кроме подсказки об уровне по умолчанию.

## 5. Модель данных контента

Все типы описаны через Zod в `src/content/schema.ts` и экспортируются как выведенные TS-типы.

### 5.1 Треки и уровни — `content/tracks.json`

```jsonc
{
  "tracks": [
    {
      "id": "cefr",
      "title": { "ru": "Уровни CEFR", "en": "CEFR levels", "sv": "CEFR-nivåer" },
      "levels": [
        { "id": "a1", "title": { "ru": "A1 — Начальный", "en": "A1 — Beginner" }, "order": 1 },
        { "id": "a2", "title": { "ru": "A2 — Базовый", "en": "A2 — Elementary" }, "order": 2 }
      ]
    },
    {
      "id": "sfi",
      "title": { "ru": "SFI", "en": "SFI (Swedish for Immigrants)", "sv": "SFI" },
      "levels": [
        { "id": "sfi-a", "title": { "ru": "SFI Курс A" }, "order": 1 },
        { "id": "sfi-b", "title": { "ru": "SFI Курс B" }, "order": 2 },
        { "id": "sfi-c", "title": { "ru": "SFI Курс C" }, "order": 3 },
        { "id": "sfi-d", "title": { "ru": "SFI Курс D" }, "order": 4 }
      ]
    },
    {
      "id": "grund",
      "title": { "ru": "Grundläggande svenska", "en": "Grund 1–4" },
      "levels": [
        { "id": "grund-1", "order": 1 }, { "id": "grund-2", "order": 2 },
        { "id": "grund-3", "order": 3 }, { "id": "grund-4", "order": 4 }
      ]
    }
  ]
}
```

`LocalizedString` = `{ ru?: string; en?: string; sv?: string }`. Порядок разрешения при выводе:
текущий язык обучения (`ru` или `en`) → второй из них → `sv` → первый доступный ключ.

Ключ `sv` внутри `LocalizedString` — это *контент* (шведские названия, атмосферные фразы),
а не шведский интерфейс: в UI поставляются только `ru` и `en`.

### 5.2 Метаданные урока — `content/lessons/<level>/<slug>/lesson.json`

```jsonc
{
  "id": "a1/greetings",
  "slug": "greetings",
  "title": { "sv": "Hälsningar", "ru": "Приветствия", "en": "Greetings" },
  "summary": { "ru": "Как здороваться и прощаться по-шведски." },
  "kind": "vocab",                       // "vocab" | "grammar" | "phrases" | "mixed"
  "levels": ["a1", "sfi-a", "sfi-b"],    // принадлежность к уровням всех треков
  "tags": ["everyday", "speaking"],
  "estimatedMinutes": 5,                 // ЖЁСТКИЙ ПОТОЛОК: 5. Длиннее — делить на части
  "part": null,                          // или { "series": "food", "index": 1, "of": 3 }
  "order": 10,                           // подсказка сортировки внутри основного уровня
  "prerequisites": [],                   // id уроков, желательных до этого (мягкое ограничение)
  "xp": { "base": 100 },                 // XP за первое прохождение
  "quiz": { "questionsPerRun": 10, "passScore": 7 },
  "cityUnlock": null                     // id здания, которое открывает этот урок (опционально)
}
```

**Правило пяти минут.** Урок должен проходиться примерно за пять минут: до ~400 слов теории и
до 25 слов в словаре плюс тест из 10 вопросов. Тема, которая не помещается, делится на серию
частей, каждая из которых — обычный самостоятельный урок:

```
content/lessons/a1/food-1/   → { "part": { "series": "food", "index": 1, "of": 3 } }
content/lessons/a1/food-2/   → { "part": { "series": "food", "index": 2, "of": 3 } }
content/lessons/a1/food-3/   → { "part": { "series": "food", "index": 3, "of": 3 } }
```

В списке уроков части показываются одной сгруппированной карточкой («Еда · 3 части») с общим
кольцом прогресса, а после завершения части экран результата сразу предлагает следующую.
При этом у каждой части свой пул, свои XP и своё состояние прохождения — серия это способ
отображения, а не единица работы.

### 5.3 Теория — `theory.md`

Обычный Markdown. Держать до ~400 слов. Дополнительно поддерживается:

- Таблицы (GFM) для спряжений и склонений.
- Блоки с языком `example` для пар предложений:

````markdown
```example
Hej! — Привет!
God morgon! — Доброе утро!
```
````

К каждой шведской строке, отрисованной из теории, автоматически добавляется кнопка озвучки.

### 5.5 Вопросы — `questions.json`

Пул состоит из **ручных вопросов + автогенерируемых**. Список из 25 слов автоматически
разворачивается в 100+ вопросов — именно это делает «100 вопросов на тему» реалистичным.

```jsonc
{
  "generators": [
    { "type": "sv-to-native-mc", "from": "vocab", "count": "all" },
    { "type": "native-to-sv-mc", "from": "vocab", "count": "all" },
    { "type": "type-answer",     "from": "vocab", "count": "all", "direction": "native-to-sv" },
    { "type": "listen-mc",       "from": "vocab", "count": "all" },
    { "type": "article",         "from": "vocab", "filter": { "pos": "noun" } },
    { "type": "plural",          "from": "vocab", "filter": { "pos": "noun" } },
    { "type": "verb-form",       "from": "vocab", "filter": { "pos": "verb" },
      "targets": ["present", "past", "supine"] }
  ],
  "items": [
    {
      "id": "q-greet-01",
      "type": "mc",
      "difficulty": 1,                    // 1..3, влияет на вес при выборке
      "prompt": { "ru": "Как сказать «Доброе утро»?" },
      "choices": ["God morgon", "God natt", "Hej då", "Tack"],
      "answer": 0,
      "explanation": { "ru": "«God morgon» — примерно до 10 утра." },
      "tags": ["greetings"]
    },
    {
      "id": "q-greet-02",
      "type": "gap",
      "prompt": { "sv": "___ morgon! Hur mår du?" },
      "answer": ["God"],
      "acceptAlso": ["god"],
```

### 5.6 Типы вопросов (v1)

| Тип | Взаимодействие | Примечания |
|---|---|---|
| `mc` | Один вариант из 4 | Клавиши `1`–`4` |
| `multi` | Несколько правильных вариантов | Возможен частичный зачёт |
| `type-answer` | Свободный ввод | Нормализация: trim, регистр не важен, `å ä ö` обязательны, пунктуация игнорируется; почти-верный ответ (расстояние Левенштейна ≤ 1) показывает «почти — проверь написание» и засчитывается с пониженным XP |
| `gap` | Вставить пропущенное в предложение | Поддержка нескольких пропусков |
| `order` | Собрать предложение из слов-фишек | Ключевой тип для шведского порядка слов (V2) |
| `match` | Сопоставление пар (3–5) | Считается за один вопрос |
| `listen` | TTS читает по-шведски, ученик выбирает/печатает | Корректно пропускается, если нет голоса `sv-SE` |
| `article` | Выбрать `en` / `ett` | Генерируется из существительных |
| `plural` | Ввести или выбрать форму множественного числа | Генерируется из существительных |
| `verb-form` | Дать форму настоящего/прошедшего/супина | Генерируется из глаголов |
| `true-false` | Верно/неверно | Дёшево писать вручную |

Каждый тип реализует один интерфейс, чтобы раннер оставался универсальным:

```ts
interface QuestionRenderer<Q extends Question> {
  Component: React.FC<{ question: Q; onAnswer: (a: Answer) => void; disabled: boolean }>;
  grade(question: Q, answer: Answer): GradeResult;   // { correct, partial?: number, feedback? }
}
```

### 5.7 Генерация неправильных вариантов

Для автогенерируемых вопросов с выбором неправильные варианты берутся **сначала из того же
урока**, затем из того же уровня, с приоритетом на ту же часть речи и похожую длину слова.
Это даёт правдоподобные, а не абсурдные варианты. Запрещено предлагать вариант, перевод
которого совпадает с переводом правильного ответа.

## 6. Логика движка тестов

### 6.1 Создание сессии

```
createSession(lessonId, opts) →
  пул = ручные вопросы ∪ сгенерированные(vocab, generators)
  доступные = пул минус вопросы предыдущей попытки
              (если после этого останется меньше questionsPerRun — ограничение снимается)
  веса:
     вопрос не встречался             → 3.0
     в прошлый раз отвечен неверно    → 2.5
     отвечен верно один раз           → 1.0
     отвечен верно 3+ раза            → 0.4
     множитель сложности              → 0.9 / 1.0 / 1.15 для сложности 1 / 2 / 3
  выбрать questionsPerRun вопросов взвешенной выборкой без возвращения
  перемешать варианты внутри вопроса по сиду сессии
```

- **Сид сессии** = `hash(lessonId + номер попытки + дата)`, сохраняется вместе с сессией,
  чтобы прогон можно было точно воспроизвести (полезно для багрепортов и тестов).
- ГПСЧ — детерминированный `mulberry32`; в коде движка **нет** `Math.random()`, поэтому тесты
  воспроизводимы.
- Смесь типов вопросов балансируется: не более 40% прогона из одного генерируемого типа.

### 6.2 Прохождение сессии

Машина состояний: `idle → вопрос → обратная связь → (вопрос | итог)`.

- Мгновенная обратная связь после каждого ответа: верно/неверно, правильный ответ, пояснение, звук.
- Правило **«одна бесплатная вторая попытка»**: первый неверный ответ в прогоне можно
  переответить один раз за половину баллов. Это подкрепление, а не наказание.
- Полоса прогресса с точками по вопросам; управление с клавиатуры (`1`–`4`, `Enter`, `Esc`).
- Выйти можно в любой момент: частичный прогресс сохраняется, но XP ниже порога не начисляется.

### 6.3 Подсчёт очков

```
correctPoints    = 10 за полностью верный ответ
partialPoints    = 5 за верный со второй попытки или частично верный
score            = верные + 0.5 * верные-со-второй-попытки   // из questionsPerRun
passed           = score >= passScore                         // по умолчанию 7 из 10

xpAwarded  = lesson.xp.base * (score / total)
           * firstPassMultiplier        // 1.0 за первое прохождение, 0.3 за повторы
           * perfectBonus               // 1.25 при score == total
           * cityPerkXpMultiplier       // от построенных зданий, например 1.10
           * streakMultiplier           // 1.0 + min(дней подряд, 10) * 0.02  → максимум 1.2

coinsAwarded = round(xpAwarded * 0.5) * cityPerkCoinMultiplier
```

**Защита от фарма:** повтор уже пройденного урока даёт 30% XP, плюс дневной лимит в
2 награждаемых прогона на урок. Ненаграждаемые прогоны всё равно обновляют историю SRS —
практиковаться можно всегда, фармить награды — нет.

### 6.4 Интервальные повторения

Каждый вопрос, который ученик видел, попадает в общую колоду повторений с планировщиком
по коробкам Лейтнера (коробки 0–5 → интервалы 0, 1, 3, 7, 16, 35 дней).

- Верно → на коробку вверх. Неверно → обратно в коробку 0.
- `/review` запускает смешанную сессию из всего, что подошло по сроку, по всем урокам.
- Ежедневное выполнение повторений даёт фиксированный бонус монетами и защищает серию дней.
- Главная страница показывает «N вопросов к повторению сегодня» как основное действие.

Всё хранится в localStorage под одним версионированным ключом: `swedish-app:v1`.

## 8. Геймификация — строим Стокгольм

### 8.1 Валюты

- **XP** — не тратится. Определяет уровень ученика и открывает эпохи. Чистая метрика прогресса.
- **Монеты (кроны)** — тратятся на здания. Начисляются за тесты, повторения, серии, достижения.
- **Серия дней (streak)** — дни подряд с активностью. Даёт множитель XP. **Заморозка серии**
  (выдаётся раз в неделю, хранится максимум 2) автоматически тратится при пропуске дня вместо
  обнуления серии.

### 8.2 Эпохи

Город проходит шесть эпох. Эпоха открывается при достижении порога XP **и** постройке нужного
количества зданий предыдущей эпохи.

| № | id эпохи | Название | Порог XP | Тема |
|---|---|---|---|---|
| 1 | `tribe` | Bosättningen (Поселение) | 0 | Хижины, костёр, первые орудия |
| 2 | `viking` | Vikingatiden (~800–1050) | 1 500 | Бирка, длинный дом, гавань, рунный камень |
| 3 | `medieval` | Medeltiden (с 1252) | 5 000 | Гамла Стан, Стурчюркан, городская стена, Риддархольмен |
| 4 | `empire` | Stormaktstiden (XVII век) | 12 000 | Верфь «Васы», Королевский дворец, Риддархусет |
| 5 | `industrial` | Industrialismen (XIX век) | 25 000 | Центральный вокзал, Скансен, Стадсхусет |
| 6 | `modern` | Moderna Stockholm | 45 000 | Метро, Avicii Arena, музей «Васа», музей ABBA |

У каждой эпохи своя палитра и свой язык материалов; береговая линия под ними не меняется
никогда. Исторические опоры, карточки эпох и правила точности для всех шести эпох — в §12.3:
эпохи это реальная история, а не фэнтезийные декорации.

### 8.4 Типы бонусов

| Бонус | Эффект |
|---|---|
| `xpMultiplier` | +N% XP с каждого теста |
| `coinMultiplier` | +N% монет с каждого теста |
| `dailyIncome` | +N монет при первом заходе за день (Гавань, Рынок) |
| `extraReviewSlots` | Больший лимит дневной сессии повторений |
| `streakFreeze` | +1 заморозка серии в неделю |
| `unlockLessonPack` | Открывает тематический набор уроков (слова викингов, экскурсия по Гамла Стан, корабль «Васа») |
| `hintToken` | Даёт бесплатные подсказки в тестах |
| `cosmetic` | Только внешний вид — украшения, сезонные скины |

Бонусы считает чистый селектор `getActivePerks(city) → PerkTotals`, чтобы движок тестов
никогда не лез напрямую в стор города.

### 8.5 Связка «обучение ↔ город»

Связь должна быть **явной и видимой**:

- Экран результата показывает: `+180 XP · +90 кр`, и если покупка стала доступна —
  «Теперь можно построить Длинный дом →».
- Карточка каждого здания описывает бонус в терминах обучения («Библиотека: +25% к объёму
  повторений»).
- Здания с `unlockLessonPack` открывают **только бонусный** контент, никогда не основную
  программу. Прогресс в языке не должен блокироваться игрой.
- Достижения связывают обе стороны: «Ordförråd 500» (500 увиденных слов), «Sju dagar i rad»
  (серия 7 дней), «Stockholms grundare» (завершить средневековую эпоху).

## 10. Требования к UI/UX

- **Mobile-first.** Учатся в основном с телефона. Зоны нажатия в тестах ≥ 44 px.
- **Тёмная тема** через стратегию `class` в Tailwind, по умолчанию — системная.
- **Переключатель языка в шапке.** Тумблер `RU / EN` в верхней панели на каждой странице.
  Он меняет **и** язык интерфейса, **и** язык перевода рядом со шведским — настройка одна,
  а не две. По умолчанию `en`. Сохраняется в localStorage под ключом `swedish-app:language`
  (пишется сразу при переключении и дублируется в файл сейва) и читается до первой отрисовки,
  чтобы не мигал неправильный язык.
  Все строки через `i18n`, захардкоженного текста в компонентах нет. Шведский — только контент,
  шведской локали интерфейса в v1 нет.
- **Честность про SFI:** на странице трека SFI короткая пометка, что разбивка по курсам —
  прагматичное приближение, а не официальная программа Skolverket.
- **Озвучка везде:** у каждого шведского слова, примера и вопроса есть кнопка динамика.
  При первом запуске один раз предупредить, если голос `sv-SE` не установлен, со ссылкой на
  инструкции для ОС.
- **Позитивная обратная связь:** волна северного сияния за идеальный прогон, анимация счётчика
  монет, ненавязчивые звуки (отключаемые), подбадривающие фразы по-шведски. Полная спецификация
  движения и тона — в §11.6–11.7.
- **Доступность:** полная навигация с клавиатуры, видимый фокус, `aria-live` для обратной
  связи, уважение `prefers-reduced-motion`, контраст ≥ 4.5:1.
- **PWA:** устанавливается, работает офлайн через service worker, кеширующий оболочку
  приложения и весь JSON контента.

## 11. Визуальный стиль — шведская национальная эстетика

### 11.1 Три слоя, которые нельзя смешивать случайно

| Слой | Где живёт | Характер |
|---|---|---|
| **Северный функционализм (funkis)** | Вся учебная поверхность: уроки, тесты, статистика, настройки | Светло, спокойно, много воздуха, честные материалы, никакого декора без функции. ~90% интерфейса |
| **Шведский фолк (Даларна)** | Тепло и праздник: разделители, пустые состояния, достижения, награды | Фалунский красный, роспись курбитс, далекарлийская лошадка |
| **Эпоха викингов / рунный камень** | Город, эпохи, бейджи | Младший футарк, змеиные ленты, резной гранит |

**Правило:** учебная поверхность — это funkis. Город может быть фолковым и викингским.
**Никогда не украшай тест** — ученик думает, и орнамент там становится шумом.

### 11.2 Палитра

Задаётся токенами Tailwind в `tailwind.config.ts`.

| Токен | Hex | Применение |
|---|---|---|
| `blue-flag` | `#006AA7` | Синий с флага. Логотип, ссылки, событие Дня Швеции. Никогда как большая заливка |
| `yellow-flag` | `#FECC00` | Жёлтый с флага. Только акцентные штрихи; никогда как текст на белом (провал по контрасту) |
| `falu` | `#7C3228` | Falu rödfärg — красный цвет всех шведских домиков. Главный тёплый акцент |
| `birch` | `#F6F2EA` | Фон светлой темы — берёза и бумага, а не чистый белый |
| `midnight` | `#0E2438` | База тёмной темы — *polarnatt*, никогда чёрный |
| `midnight-surface` | `#16324B` | Карточки тёмной темы |
| `granite` | `#4A5259` | Вторичный текст, камень, границы |
| `pine` | `#2F4A3C` | Хвойный зелёный — успех |
| `gold` | `#C8A24A` | Монеты и награды. Теплее и спокойнее флажного жёлтого |
| `lingon` | `#C0392B` | Ошибки — чётко отличается по тону и светлоте от `falu` |
| `aurora` / `aurora-violet` | `#3FBF9F` / `#7B6CD9` | Градиент северного сияния. **Только праздник**, никогда интерфейс |

Контраст ≥ 4.5:1 в обеих темах. Цвета флага — приправа, а не основа: интерфейс, залитый
синим и жёлтым, читается как спортивная форма, а не как шведский дизайн.

### 11.3 Типографика

- **Текст / интерфейс: Inter** (variable). Покрывает латиницу, кириллицу и `å ä ö`.
- **Заголовки эпох: Cormorant Garamond** — есть кириллица, даёт исторический регистр.
  Не больше одного акцидентного шрифта.
- **Жёсткое правило:** шрифт не проходит, если не отрисовывает **и** `å ä ö`, **и** кириллицу.
  Тестовая строка: `Skärgård fjäll Öland — Шведский язык`.
- **Не использовать Sweden Sans** — это официальный национальный шрифт Швеции с ограниченной
  лицензией, он не бесплатен для сторонних продуктов.
- **Не использовать «викингские» и готические декоративные шрифты.** Нет кириллицы, нечитаемо
  в интерфейсных размерах и исторически неверно: скандинавы резали руны, а не писали готикой.
- Шведские слова внутри текста набираются на одну ступень жирнее (semibold), чтобы изучаемый
  язык всегда вёл взгляд.

### 11.4 Орнамент и иконография

- **Далекарлийская лошадка (dalahäst)** — маскот приложения и спиннер загрузки. Плоский
  силуэт, фалунский красный, седло с курбитсом. Родом из резьбы по дереву Даларны XVII века.
- **Курбитс** — народная цветочная роспись Даларны. Разделители секций, рамки достижений,
  пустые состояния.
- **Восьмилепестковая северная звезда** — маркер списка, иконка серии дней, разделитель.
- **Младший футарк** (16 рун — тот алфавит, которым реально писали в Швеции эпохи викингов) —
  орнамент эпохи 2 и печати достижений. **Никогда старший футарк, никогда руны Толкина.**
- **Змеиная лента (ormslinga)** — лента надписи с упландских рунных камней, как рамка вокруг
  заголовков эпох.
- Иконки: база `lucide-react` плюс свои SVG под шведскую специфику — dalahäst, kanelbulle,
  midsommarstång, буква `T` метро.
- **Никаких рогатых шлемов. Никогда.** Это выдумка оперного костюма XIX века. Один такой шлем
  тихо обесценивает всё, что написано в разделе 12.

### 11.5 Стиль иллюстраций города

- Плоский вектор SVG, единая обводка 2 px, ограниченная палитра на эпоху, без фотореализма
  и без градиентов, кроме праздничного сияния.
- Намеренная неровность резьбы — линии с лёгким дрожанием, как в ксилографии.
- Псевдоизометрия: здания смотрят фронтально с одной небольшой боковой плоскостью.
  Это резко удешевляет отрисовку.
- Материалы меняются по эпохам: шкуры и брёвна → дерево и железо → кирпич и известковая
  штукатурка → барочный камень → красный кирпич, железо и стекло → бетон, стекло и свет.
- **Фон карты постоянен:** береговая линия Меларена и остров Стадсхольмен. Вода и скалы не
  меняются никогда, меняется только то, что на них стоит. Именно это делает шесть эпох
  одним местом во времени, а не шестью разными картинками.

### 11.6 Движение

- По умолчанию спокойно: 150–200 мс, ease-out. Приложение должно ощущаться как бумага
  и дерево, а не как игровой автомат.
- Идеальный прогон → волна северного сияния и золотые монеты, максимум 1.2 с.
- Здание построено → оно «вырезается» на месте: сначала обводка, потом заливка.
- Веха серии дней → лоза курбитс обвивает счётчик.
- Всё перечисленное отключается при `prefers-reduced-motion`.

### 11.7 Голос

- Микрокопия обратной связи — **на шведском**: `Bra jobbat!` `Nästan!` `Perfekt!` `Heja!`
  `Lycka till!` `Vi ses!` — с переводом при первой встрече и по наведению.
- Тон — **lagom**: тепло, сдержанно, уверенно. Никаких `ПОТРЯСАЮЩЕ!!!`, никаких россыпей
  восклицательных знаков, никакой манипулятивной срочности. Шведский дизайн не кричит,
  и это приложение тоже.

## 12. Историческая тема — викинги и история Швеции и Стокгольма

### 12.1 Зачем история держит игру

Строительство города — это петля награды, и она построена на **настоящей** истории, поэтому
награда тоже учит. Каждая эпоха привязана к реальным событиям, каждое здание — к реальному
месту. Ученик, прошедший игру, знает Стокгольм, а не выдуманный городок.

### 12.2 Честная рамка

Стокгольм впервые упоминается в письменных источниках в **1252 году**. Значит, эпохи 1–2 —
это *не* Стокгольм, а регион Меларена, из которого он вырос; Бирка находится примерно в 30 км
западнее, на острове Бьёркё. Об этом надо прямо сказать во вступлении к эпохе, а не делать вид,
что викинги ходили по Гамла Стан. Береговая линия на карте одна и та же всё время; сам город
появляется в третьей эпохе.

### 12.3 Исторические опоры эпох (проверенные факты для карточек эпох и контента)

**Эпоха 1 — Bosättningen (доисторическое время)**
- Первые поселенцы идут за отступающим ледником, примерно 12 000 лет до н. э.
- Наскальные изображения бронзового века (*hällristningar*) в Тануме — объект ЮНЕСКО.
- *Ales stenar* в Сконе — каменный корабль из 59 валунов, около 600 года н. э.
- Здания: хижина, костёр, наскальный рисунок, каменный корабль, охотничьи угодья.

**Эпоха 2 — Vikingatiden, ок. 750–1050**
- **Бирка** на острове Бьёркё в озере Меларен, ок. 750–975 — один из древнейших городов
  Скандинавии; объект ЮНЕСКО вместе с Ховгорденом.
- Христианская миссия Ансгара доходит до Бирки около 830 года.
- Только в Упланде около **2 500 рунных камней** — самая высокая плотность в мире.
- Шведы ходили **на восток**: Балтика, реки Руси, Миклагард (Константинополь). Поход Ингвара
  Путешественника около 1040 года увековечен примерно на 25 рунных камнях.
- Письменность — **младший футарк**, 16 рун.
- *«Викинг» — это то, что ты делал* (торгово-военный поход), а не народ. Народами были норманны,
  свеи и гёты. Карточка эпохи говорит об этом прямо.
- Здания: длинный дом, гавань с *långskepp*, рунный камень, торговая площадь Бирки, кузница,
  место тинга (*ting*).

**Эпоха 3 — Medeltiden, с 1252**
- Стокгольм впервые появляется в документах в **1252 году**, в письмах, связанных с Биргером Ярлом.
- **Стурчюркан** (Storkyrkan), XIII век — главный храм города.
- **Риддархольмская церковь**, францисканский монастырь 1270–80-х годов — усыпальница королей.
- *Mårten Trotzigs gränd* — 90 см в самом узком месте, самый узкий переулок Гамла Стан.
- *Stockholms blodbad* — Стокгольмская кровавая баня, ноябрь 1520 года.
- Здания: городская стена, Стурчюркан, рынок на Стурторьет, портовый кран, гильдейский дом,
  Риддархольмен.

**Эпоха 4 — Stormaktstiden, 1611–1721**
- **«Васа»** опрокинулся в первом же плавании **10 августа 1628 года**, едва в 1 300 м от верфи.
  Поднят в **1961**; музей Vasamuseet открыт в **1990** и остаётся самым посещаемым музеем
  Скандинавии.
- Замок Тре Крунур сгорел в **1697**; нынешний **Королевский дворец** достроен в 1754 году.
- **Риддархусет**, Дом дворянства, 1660-е.
- Здания: верфь, сам «Васа», Риддархусет, королевский дворец, обсерватория, смоляная гавань.

**Эпоха 5 — Industrialismen, XIX век**
- **Центральный вокзал Стокгольма**, 1871.
- **Скансен**, 1891, основан Артуром Хазелиусом на Юргордене — первый в мире музей под
  открытым небом.
- Первое вручение **Нобелевской премии** — 1901.
- **Стадсхусет** (ратуша), 1923, архитектор Рагнар Эстберг — Нобелевский банкет проходит
  в *Blå hallen*, Синем зале, который знаменит тем, что не синий.
- Здания: центральный вокзал, газовый завод, Скансен, ратуша, трамвайная линия, Нобелевский зал.

**Эпоха 6 — Moderna Stockholm**
- **Метро** открыто в 1950 году; около 90 из 100 станций оформлены художниками — отсюда
  название *самая длинная художественная галерея мира*.
- **Globen**, 1989, переименован в **Avicii Arena** в 2021 году.
- **ABBA** выиграла Евровидение в 1974 году с *Waterloo*; музей ABBA открыт в 2013 году.
- **Слюссен** перестраивается; Золотой мост установлен в 2020 году.
- Здания: станция метро с искусством, Avicii Arena, музей «Васа», музей ABBA, Слюссен,
  Fotografiska.

### 12.4 Исторические карточки — `content/history/`

Новый лёгкий тип контента: **это не урок** — нет теста, нет порога, нет блокировки XP.
120–200 слов, дата, иллюстрация и 5–8 ключевых шведских слов.

```jsonc
{
  "id": "birka",
  "era": "viking",
  "unlockedBy": "trading-square",       // id здания
  "title": { "sv": "Birka", "ru": "Бирка", "en": "Birka" },
  "date": { "from": 750, "to": 975 },
  "body": { "ru": "…", "en": "…" },
  "vocab": ["handel", "skepp", "silver", "resa", "hamn"],
  "image": "/img/history/birka.svg",
  "sources": ["Список всемирного наследия ЮНЕСКО, Бирка и Ховгорден", "Riksantikvarieämbetet"]
}
```

Прочтение карточки даёт разовую небольшую награду монетами, а **её слова попадают в колоду
повторений** — так история, которую ученик читает ради интереса, тихо превращается в языковую
практику, которую у него потом спросят. Это самый дешёвый и самый изящный мост между игрой
и обучением.

### 12.5 Тематические паки уроков от зданий

Бонус `unlockLessonPack` открывает настоящие, полезные уроки:

| Здание | Пак | Содержание |
|---|---|---|
| Рунный камень | `viking-words` | `skepp`, `hamn`, `handel`, `resa`, `sten`, `rista`, `minne` плюс формула рунных надписей: *«X lät resa stenen efter Y»* |
| Стурчюркан | `gamla-stan` | Ориентирование в Старом городе: `gränd`, `torg`, `kyrka`, `slott`, `bro`, направления |
| «Васа» | `vasa-ship` | Корабельная и музейная лексика плюс история гибели простым шведским |
| Станция метро | `tunnelbanan` | Названия станций, направления, билеты, реальные объявления: *«Nästa station …»*, *«Dörrarna stängs»* — сразу полезно любому, кто живёт в Стокгольме |
| Скансен | `svensk-kultur` | `fika`, `midsommar`, `lucia`, `allemansrätten`, `lagom` |

Паки — **бонусный** контент. Основная программа никогда не блокируется игрой.

### 12.6 Правила исторической точности

- У каждого исторического утверждения есть дата, и даты проверяются до коммита.
- Поле `sources` **обязательно** на каждой исторической карточке.
- **Мифы, которые мы сознательно не используем:** рогатые шлемы; «викинги» как народ или раса;
  старший футарк в контексте эпохи викингов; и «Биргер Ярл основал Стокгольм в 1252 году» —
  1252-й это первое письменное *упоминание*, становление города было постепенным, а авторство
  Биргера Ярла традиционно, но документально не подтверждено. Пишем «впервые упомянут»,
  а не «основан».
- *Jantelagen* происходит из романа Акселя Сандемусе 1933 года и по происхождению
  датско-норвежский, хотя его постоянно прикладывают к Швеции. Если культурная карточка его
  использует — она это оговаривает.
- Спорные утверждения получают оговорку («по традиции», «согласно сагам»), а не удаляются.
  Приложение должно показывать честную историю, а не причёсанную.
- Не романтизируем набеги. Эпоха была торговлей, ремеслом, путешествиями и расселением не
  меньше, чем насилием — и это одновременно и лучший вкус, и более точная история.

### 12.7 Сезонные скины по реальному календарю

| Дата | Событие | Оформление |
|---|---|---|
| 13 декабря | **Люсия** | Свечи по всему городу, глубокая синяя ночная палитра, иконка *lussekatt* |
| Июнь | **Мидсоммар** | *Midsommarstång* на карте, берёзовые гирлянды, венки |
| 4 октября | **Kanelbullens dag** | Иконка булочки с корицей, бонус монет за фику |
| 6 июня | **Национальный день** | Флаги — единственный день в году, когда синий и жёлтый забирают весь интерфейс |
| Адвент | **Адвент** | Звёздные светильники *adventsstjärna* в окнах каждого здания |

К каждому событию — один маленький урок ограниченного времени. Дёшево в производстве,
сильный повод вернуться.

## 13. Локальная разработка

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # → dist/
npm run preview      # локально отдать продакшен-сборку
npm run typecheck
npm run lint
npm run test
npm run validate     # Zod-валидация всех файлов контента
npm run new:lesson   # интерактивный генератор урока
```

`npm run validate` обязан входить в `npm run test` и в CI. Ошибкой считается:

- отсутствие перевода `ru` или `en` у любого слова или пользовательской строки;
- дублирующийся id вопроса или урока;
- индекс `answer` вне диапазона или пул меньше `questionsPerRun`;
- `estimatedMinutes > 5`, больше 25 слов в словаре или теория длиннее ~400 слов —
  правило пяти минут, проверяемое машиной;
- неполная серия `part` (пропуски в `index` или `of`, не совпадающее с числом найденных уроков);
- ссылка из учебного курса на несуществующий id урока.

Добавить **дев-панель контента** (`?dev=1`) со списком всех уроков: размер пула, число
сгенерированных вопросов, предупреждения валидации.

## 14. Деплой на GitHub Pages

`vite.config.ts`:

```ts
export default defineConfig({
  base: '/swedish/',        // имя репозитория — `swedish`, зафиксировано, см. раздел 0
  plugins: [react()],
});
```

- Адрес сайта: `https://<user>.github.io/swedish/`. В `index.html` стоит `<title>Swedish</title>`,
  в `manifest.webmanifest` — `"name": "Swedish"`, `"short_name": "Swedish"`,
  `"start_url": "/swedish/"`, `"scope": "/swedish/"`.

  `actions/setup-node@v4` (node 20, кеш npm), `npm ci`, `npm run validate && npm run build`,
  `actions/upload-pages-artifact@v3` с `path: dist`, `actions/deploy-pages@v4`.
  Права: `contents: read`, `pages: write`, `id-token: write`.
- Workflow `validate.yml` на пул-реквестах: typecheck, lint, тесты, валидация контента.

## 15. Процесс создания контента

1. `npm run new:lesson` → спрашивает уровень, slug, название, тип → создаёт папку с шаблонными
   `lesson.json`, `theory.md`, `vocab.json`, `questions.json`.
2. Заполнить 15–25 слов (25 — жёсткий потолок, см. правило пяти минут). Генераторы развернут
   их в 100+ вопросов.
3. Добавить 10–20 ручных вопросов на то, что генераторы не умеют (порядок слов, идиомы,
   культура, грамматические ловушки).
4. `npm run validate` → исправить ошибки.
5. Прописать id урока в нужных файлах учебных курсов.
6. Закоммитить. CI проверит и задеплоит.

**Правила качества контента:**

- У каждого шведского существительного обязательны `gender` и все четыре формы `forms`.
- У каждого глагола обязательны `verbGroup` и все четыре основные формы.
- У каждого слова желателен пример `example` — именно он реально учит употреблению.
- У каждого слова обязательны **оба** перевода — `ru` и `en`: переключатель в шапке может
  сработать в любой момент, отсутствующий язык — это видимая дыра, валидация её не пропустит.
- Урок должен укладываться в 5 минут. Если не укладывается — делить на части, а не урезать
  объяснение.
- Пояснения пишутся для ученика, а не для автора: объясняй *почему*, а не только *что*.

## 16. Этапы реализации

**Этап 1 — Каркас (день 1)**
Vite + React + TS + Tailwind + роутер + AppShell. Палитра и типографика из §11 закладываются
в `tailwind.config.ts` **сразу**, а не потом: натягивать визуальный стиль на готовые экраны
в разы дороже, чем начать с него. Шапка с тумблером `RU / EN`. Пустые страницы, зелёный
пайплайн деплоя, сайт живёт на GitHub Pages.

**Этап 2 — Пайплайн контента**
Zod-схемы, загрузчик `import.meta.glob`, реестр, скрипт валидации, 3 демо-урока A1.
Страницы треков, уровней и списка уроков рендерят реальный контент.

**Этап 3 — Страница урока**
Рендер теории, таблица слов, карточки слов, TTS.

**Этап 4 — Движок тестов**
ГПСЧ, выборка, генераторы, проверка ответов, UI раннера, типы `mc` / `type-answer` / `gap`,
экран результата. Юнит-тесты движка и проверки ответов.

**Этап 5 — Прогресс и награды**
Сторы Zustand, персист с миграциями, XP/монеты, серия дней, экспорт/импорт, страница статистики.

**Этап 6 — Остальные типы вопросов**
`order`, `match`, `listen`, `article`, `plural`, `verb-form`, `multi`, `true-false`.

**Этап 7 — Интервальные повторения**
Планировщик Лейтнера, страница `/review`, счётчик к повторению на главной.

**Этап 8 — Город**
Эпохи, здания, магазин, селекторы бонусов, карта города, достижения, праздничное сияние.
Карточки эпох с историческими опорами из §12.3.

**Этап 8b — Исторический слой**

## 18. Дополнительные идеи (предложения сверх исходного задания)

Всё это расширяет принцип «много способов учить с позитивным подкреплением».
Отсортировано по соотношению пользы к трудозатратам.

1. **Ежедневный вызов** — 5 смешанных вопросов из всего пройденного, одна попытка в день,
   щедрая награда монетами. Сильнейший механизм формирования привычки без сервера.
2. **Режим карточек** — колода на урок со свайпом/клавиатурой, без оценок, чистое повторение.
   Иногда человек не хочет, чтобы его проверяли.
3. **Слово дня** — карточка на главной с озвучкой и примером. Бесплатные монеты за прослушивание.
4. **Мастерская предложений** — из известных слов собирать предложения типом `order`; учит
   шведскому порядку слов (V2) — главной стене для начинающих.
5. **Диктант на слух** — TTS читает предложение, ученик его печатает. Очень полезно и
   бесплатно благодаря `speechSynthesis`.
6. **Тренировка произношения** — Web Speech API *recognition* (`sv-SE`) оценивает сказанное
   слово. Только Chrome, деградировать мягко. Очень «вау»-эффект.
7. **Музей ошибок** — страница личных повторяющихся ошибок («ты путаешь `en`/`ett` вот на этих
   12 существительных») с тренировкой в один тап. Превращает провалы в фичу.
8. **Тематические паки уроков от зданий** — постройка верфи «Васы» открывает урок про корабль
   «Васа» (реальные слова + культура). Делает город осмысленным, а не декоративным.
9. **Карточки шведской культуры** — fika, allemansrätten, midsommar, lagom, jantelagen.
   Открываются как награды за эпохи; коротко, приятно, запоминается.
10. **Тепловая карта активности** — сетка в стиле контрибуций GitHub на `/stats`.
    Дёшево и очень мотивирует.
11. **Витрина достижений** — бейджи отображаются на карте города как монументы.
12. **Карточка результата для шеринга** — рендер PNG через canvas за идеальный прогон.
    Бэкенд не нужен.
13. **Сезонные события** — Lucia (13 декабря), Midsommar, Kanelbullens dag (4 октября):
    временные уроки и украшения города. Дешёвый контент, большой возврат пользователей.
14. **Локальный рейтинг против себя прошлого** — «эта неделя против прошлой». Не требует сервера.
15. **Опциональная синхронизация (v2)** — GitHub Gist или Supabase, только по желанию,
    чтобы v1 оставался без бэкенда.

### Оставшиеся открытые вопросы

Все вопросы к запуску закрыты в разделе 0. Открытым остаётся только то, что касается v2:

- Свой домен через `CNAME` вместо подпути `/swedish/` — это изменит `base` в Vite.
- Стоит ли добавлять шведскую локаль интерфейса, когда приложение будет функционально готово.
- Стоит ли опциональная облачная синхронизация (идея 15) потери свойства «без бэкенда».
